# 向量数据库与元数据管理实战

**基于 LangChain + 阿里 DashScope 通义大模型 + FAISS 向量库**的 PDF 文档 RAG 检索问答系统，专门读取银行考核制度 PDF，提问后返回答案并标注答案来源 PDF 页码

完整流程：

PDF 读取 → 全文提取 + 记录每页文本对应页码 → 文本切块 → 向量嵌入构建 FAISS 库（持久化保存）→ 问题相似度检索 → 大模型基于匹配文本回答 → 输出答案 + 来源页码。


**==Q：这个项目中元数据是怎么被管理的？==**

这段代码**完全自定义实现元数据管理**，没有使用 LangChain FAISS 标准`Document.metadata`，而是自建一套独立映射体系：

- 用字典 `page_info: {文本块: 页码}` 存储元数据（页码）；
- 用`pickle`序列化单独保存到`page_info.pkl`文件，和 FAISS 向量索引文件分离；
- 挂载到 FAISS 对象自定义属性 `.page_info` 全局携带，检索时通过文本块反向匹配页码。

这种属于**外置独立元数据存储方案**，和 Redis、SQLite 外置元数据逻辑同源，只是用本地文件替代数据库。
